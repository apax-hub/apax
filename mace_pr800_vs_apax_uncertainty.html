Uncertainty in MACE: two independent designs land on the same week

MACE PR #800 (Hubert Beck, ACEsuit/mace, branch multihead-committee) and apax feat/mace-foundation-integration both add an ensemble-style uncertainty head on top of a single shared MACE descriptor. They differ in framework, in how the ensemble is embedded in the graph, and in how forces flow through it.

What is MACE, and where do we hook in?

MACE is a message-passing GNN whose messages are e3-equivariant tensor products of a radial basis and spherical harmonics, then raised to a many-body symmetric tensor power (the “ACE” part). Per-layer scalar readouts turn node features into a per-atom energy. The ensemble surgery in both PR #800 and apax happens entirely inside the readout slot — the descriptor stays unchanged.

Zoom on the readout slot

In stock MACE the readout produces one scalar per atom per layer. Both designs replace that final width-1 projection with a wider one; everything before it is bit-for-bit identical to a stock MACE forward pass.

Where the ensemble lives

Same descriptor, different last-mile. PR #800 makes per-head structurally separate readouts; apax makes one wider readout whose extra dimension is the ensemble axis.

The readout block, side by side

Both designs widen the final projection. PR #800 keeps separate linear_1 / linear_2 per head via e3nn instructions. apax just emits n_out × 0e from a single Linear and lets vmap + autodiff do the rest.

MACE PR #800 · mace/modules/blocks.py
class NonLinearReadoutBlock(torch.nn.Module):
    def __init__(self, irreps_in, MLP_irreps, gate,
                 irrep_out=o3.Irreps("0e"), num_heads=1, ...):
        # heads stay disjoint: only the i-th input chunk feeds the i-th head
        instructions_1 = [(0, i) for i in range(num_heads)] if num_heads > 1 else None
        self.linear_1 = Linear(
            irreps_in=irreps_in,
            irreps_out=num_heads * MLP_irreps,
            instructions=instructions_1, ...)
        self.non_linearity = nn.Activation(
            irreps_in=num_heads * MLP_irreps, acts=num_heads * [gate])
        instructions_2 = [(i, i) for i in range(num_heads)] if num_heads > 1 else None
        self.linear_2 = Linear(
            irreps_in=num_heads * MLP_irreps,
            irreps_out=num_heads * irrep_out,
            instructions=instructions_2, ...)

    def forward(self, x):
        x = self.non_linearity(self.linear_1(x))
        return self.linear_2(x)   # [n_nodes, num_heads]

class NonLinearReadoutBlock(nn.Module):
    MLP_irreps: str = "16x0e"
    silu_normalization: float = 1.6791767923989418  # match torch-e3nn normalize2mom
    n_out: int = 1

    @nn.compact
    def __call__(self, feat):
        x = e3nn.flax.Linear(self.MLP_irreps, name="linear_1")(feat)
        x = e3nn.IrrepsArray(x.irreps,
                             jax.nn.silu(x.array) * self.silu_normalization)
        out = e3nn.flax.Linear(f"{self.n_out}x0e", name="linear_2")(x)
        return out.array          # (n_out,) per atom under vmap

# apax/layers/readout.py
class MaceReadout(nn.Module):
    num_interactions: int
    hidden_dim: int
    n_shallow_ensemble: int = 0
    @nn.compact
    def __call__(self, x):
        n_out = self.n_shallow_ensemble if self.n_shallow_ensemble > 0 else 1
        E = jnp.zeros((n_out,))
        for k in range(self.num_interactions):
            feat = e3nn.IrrepsArray(f"{self.hidden_dim}x0e",
                                    x.reshape(self.num_interactions, self.hidden_dim)[k])
            E = E + (LinearReadoutBlock(n_out=n_out, ...)(feat)
                     if k < self.num_interactions - 1
                     else NonLinearReadoutBlock(n_out=n_out, ...)(feat))
        return E

Side-by-side comparison

Where the two designs sit on each axis.

Axis MACE PR #800 (multihead-committee) apax (feat/mace-foundation-integration)
Framework PyTorch, e3nn-pytorch, optional cuEquivariance (currently bypassed for multi-head). JAX + flax + e3nn-jax. MACE is re-implemented natively (apax/layers/descriptor/mace_blocks.py).
How the ensemble is embedded Multiple named heads committee-0..N-1; each head owns its own readout slice via e3nn instructions. A single readout that emits n_out × 0e; the ensemble lives as the trailing dim of E_i.
Forces / gradients Python loop in get_outputs_committee calls autograd.grad per head with retain_graph=True. PR description flags this as costlier than ideal. One JAX backward through the whole (N, n_ensemble) tensor; force stack falls out naturally with vmap.
Uncertainty loss New MixedNllMseLoss selected via --loss dpose: NLL on energy, MSE on forces. Per-property pluggable: nll_loss (Gaussian NLL) or crps_loss (Gaussian CRPS) driven by the matching <name>_uncertainty channel.
Data partitioning --disjoint_committee shards the train set per head (bagging-style). Heads share data; diversity comes from independent random init and (on transfer) the reset_layers targeted reinit.
Foundation models Not addressed — finetuning still works through MACE's existing load_foundations_elements, but no committee-specific support. First-class: apax convert mace ... emits a real apax checkpoint from MACE-MP / MPA; finetune flow uses TransferLearningConfig.reset_layers to swap in ensemble readouts.
Inference / ASE MACECalculator(..., multihead_committee=True) exposes energy_stds and force_stds. make_ensemble wraps any model and auto-augments the result dict with *_uncertainty + raw *_ensemble; transparent to ASE / MD / BAL.
Known limitations Forces recomputed per head (acknowledged); cuEquivariance disabled for multi-head; tests + docs flagged as TODO. Shallow ensemble shares the descriptor — uncertainty calibration depends on readout-only diversity; deep ensembles are still needed for stronger guarantees.

So which is which, and when?

The two approaches are complementary, not competing.

Pick MACE PR #800 when
  • You are already training a MACE model from scratch in PyTorch and want uncertainty without managing N independent checkpoints.
  • You want explicit control of per-head training sets (--disjoint_committee).
  • You can live with the per-head autograd cost on forces (the PR author flags this as the main remaining problem).
  • You do not need cuEquivariance for the multi-head readout (currently asserted off).
Pick apax feat/mace-foundation-integration when
  • You want to take a published MACE foundation (MACE-MP-0, MPA-0, ...) and only train a small ensemble head on your downstream data.
  • You want forces and stresses through the ensemble for ~free (one JAX backward, not one per head).
  • You want to mix uncertainty into MD / active learning through the existing apax stack (ASE calculator, BAL, ZnDraw).
  • You want the loss to be a knob per property, not a single hard-coded combination.
