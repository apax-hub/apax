MACE integration fixes — design spec

apax · branch feat/mace-foundation-integration · delivered as phased direct commits on that branch (no PRs).

Date 2026-06-01 · Scope decided: buckets A (done, separate) + B + C + E, with bucket D deferred to loud guards (Approach 2, phased).

1 · Context & goal

An audit of how MACE was added to apax surfaced issues on three axes: (1) framework-wide uncertainty math, (2) consistency with apax's documented four-layer model-extension pattern, (3) mathematical parity with the reference MACE repos. The math path is verified correct end-to-end (foundation energy parity 1.6e-7 eV vs torch MPA-0); the real work is convention/structure hardening plus restoring the MACE feature path.

Bucket A (general UQ) — already shipped separately. The PropertyHead variance-vs-std bug and the make_ensemble 1/N→1/(N−1) estimator were framework-wide (not MACE), so they landed in PR #561 against main (done). This spec covers only the MACE-specific buckets on the feature branch.

3 · Phase 1 — commits

Commit 1 — B: fix the MACE feature / BAL path

Problem. MaceBuilder.build_readout(is_feature_fn=True) (builder.py:381-384) routes to super().build_readout, which builds an AtomisticReadout([256,256]) from the inherited (unused) nn field. The converter/training only ever populate MaceReadout params, so feature extraction hits a param-tree mismatch or runs an untrained random MLP. ASE get_descriptors and BAL are broken for MACE.

Fix. Return None for the MACE feature readout. FeatureModel.__call__ does if self.readout: features = jax.vmap(self.readout)(features), so None yields the real, trained descriptor features (n_atoms, num_interactions·hidden_dim). Raise a clear NotImplementedError if only_use_n_layers is not None (partial-layer features deferred to Phase 2).

Test: build_feature_model().init/apply on a tiny MACE config → finite features of expected width; partial-layer request raises the documented error.

Commit 2 — C: converter resilience to module-name drift

Problem. mace_foundation.py hard-codes Flax auto-names (InteractionBlock_{k}, ProductBlock_{k}, LinearNodeEmbedding_0, readout_{k}); renaming any submodule breaks conversion with a deep KeyError.

Fix. Replace brittle string indexing with structural slot-discovery (extend the pattern already in _map_readouts, ~:1029-1041): enumerate submodule keys present in the pytree, map by position/role, raise an actionable error if the expected count/shape is absent. Preserves loud-failure behavior, removes silent-drift hazard.

Commit 3 — C: base-builder leak, n_species threading, union tidy

  • Move the basis_config.get("variant") / MaceBesselBasis branch out of ModelBuilder.build_basis_function (builder.py:53-68) into MaceBuilder — the shared base no longer knows about MACE.
  • Replace converter module-constant _N_SPECIES = 119 (mace_foundation.py:31) by threading the builder's n_species.
  • DistanceTransformConfig = Union[AgnesiTransformConfig] → Annotated[Union[...], Field(discriminator="name")] (model_config.py:198), matching sibling InteractionConfig.

Commit 4 — D-guards + dead-code removal D deferred

  • Loud NotImplementedError in the converter for a non-Residual first interaction block (_TORCH_TO_APAX_INTERACTION, mace_foundation.py:25-27 / 248-253), naming the unsupported block and that it is intentionally unimplemented (no shipped foundation needs it).
  • Comment at the dr_vec sign site (distances.py:61 / mace.py) documenting that the opposite edge-vector convention vs torch-MACE is absorbed by the scalar readout's inversion symmetry (verified by parity).
  • Delete dead code: _extract_norm_consts (mace_foundation.py:1049-1088) and the discarded _scalar_irreps_only result (mace.py:102).

Commit 5 — E: doc-deck fixes in mace_pr800_vs_apax_uncertainty.html

  • Slide 4: instructions_1 is [(0,i) …], not [(i,i) …].
  • Slide 4: drop the apax-only n_out factor from the MACE irreps_out description (PR #800 heads emit a single 0e).
  • Slides 4 & 6: soften the "single backward pass" claim — apax uses jax.jacrev + an optional chunk-loop, i.e. O(n_ensemble) VJPs, vectorized/JIT'd (not one VJP).

4 · Phase 2 — decouple the readout

Problem (B1). MaceReadout reshapes the flat descriptor blob back into per-layer chunks using num_interactions/hidden_dim passed from config (readout.py:110-115, builder.py:404-413) — an implicit, undocumented packing contract that couples readout to descriptor internals.

Design.

  • MaceRepresentation emits an explicit per-layer feature array (n_atoms, n_layers, hidden_dim) instead of a flattened (n_atoms, n_layers·hidden_dim) blob. This becomes a documented "structured per-layer feature" variant of the descriptor contract.
  • MaceReadout derives n_layers and hidden_dim from x.shape (vmapped per atom it sees (n_layers, hidden_dim)), dropping the num_interactions/hidden_dim config arguments. Renaming/resizing the descriptor can no longer desync the readout — the shape carries the info.
  • Builder stops passing the two coupling args to _build_mace_readout.
  • Feature extraction (Commit 1) naturally exposes the structured features; partial-layer features (only_use_n_layers) become a simple slice on the layer axis — closes the Phase-1 deferral.
Parity is the gate. This touches the descriptor→readout→builder seam and the converter's readout mapping (per-layer weights must still land correctly). Re-run test_mace_parity.py / test_mace_s22_parity.py and reproduce 1.6e-7 eV before committing. If the converter relied on the flat layout, update its readout slot-discovery (Commit 2) accordingly.

5 · Phase 3 — docs

Update docs/adding_new_models.html to document the structured per-layer feature contract as a first-class supported variant (alongside the existing flat (n_atoms, n_features) contract), so a future per-layer-readout model has a sanctioned pattern to follow rather than re-deriving MACE's coupling.

6 · Deferred (out of scope) — bucket D math

The non-residual first interaction block and the interaction_irreps_first vs interaction_irreps distinction cannot fire on any shipped MACE foundation (all Residual-first, no odd-parity scalar hidden irreps). We implement only the loud guard (Commit 4), not the math — YAGNI until a target foundation requires it.

7 · Conventions & gates

  • All commands via uv run / uvx; numpy-style docstrings; never modify @pytest.mark.protected tests.
  • TDD per concern: write the failing test first, then the change.
  • uvx prek --all-files clean before each commit.
  • Phase boundary = MACE parity suite green (skips cleanly when local foundation files are absent; run where available).
