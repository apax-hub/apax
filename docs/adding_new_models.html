Adding new models to apax

apax is an atomistic machine-learning potential framework built on JAX & Flax. Its model system is deliberately modular: a model is the composition of a descriptor, a readout, a scale/shift, optional property heads and empirical corrections — all wired together by a builder that is selected by a Pydantic config. This guide traces those parts through the codebase and shows you exactly how to add a new one.

config → get_builder() → builder → model descriptor + readout + scale_shift jax · flax.linen · pydantic v2

01 Overview & design philosophy

apax separates what a model is (declarative config) from how it is assembled (a builder) from how it computes (flax modules). Adding a model means slotting new pieces into these seams — almost never editing the core.

The contract in one breath

A config is a Pydantic model that knows which builder to return. The builder assembles a flax model out of reusable layers. Training, MD and the ASE calculator all go through the same builder, so a new model gets forces, stress, ensembles, property heads and checkpointing for free.

The single mandatory override

To add a model you implement one abstract method — ModelBuilder.build_descriptor() — plus a Pydantic config class and a Flax descriptor module. Everything else (readout, UQ, MD, checkpointing) is inherited. You override more only when your architecture genuinely needs it.

📌
Reference models. apax ships three models — GMNN (Gaussian Moment NN), EquivMP (equivariant message passing) and So3krates. They all live in the same config / builder / descriptor seams described here, so the quickest way to scaffold a new model is to copy the closest existing one and adapt its descriptor.

04 How Pydantic configures models

Configuration is not a dict of strings — it is a tree of validated Pydantic v2 models. The central trick is the discriminated union: a tag field (name or kind) selects which subclass a YAML block parses into.

Discriminated unions everywhere

Each "pluggable choice" in a config is a Union discriminated by a literal tag. Adding an option = adding a class with a new literal and appending it to the union.

From YAML to a validated object

apax/config/common.py
def parse_config(config, mode="train"):
    if isinstance(config, (str, os.PathLike)):
        with open(config) as s:
            config = yaml.safe_load(s)
    if mode == "train":
        config = Config.model_validate(config)  # ← validate + pick subclass

A YAML block model: {name: so3krates, …} is routed to So3kratesConfig automatically by the name discriminator. Unknown keys raise (extra="forbid") — your best friend against silent typos.

Two things the rest of the code relies on

model_dump() The builder consumes a plain dict, not the Pydantic object: Builder(config.model.model_dump(), n_species=119). Inside a builder you therefore use self.config["n_contr"], not attribute access.

model_json_schema() apax schema calls Config.model_json_schema() and writes apaxtrain.schema.json for VS Code YAML autocompletion. Your new fields and docstrings show up in editors for free.

💡
Nested variant configs. For a model with sub-choices (e.g. several block or basis variants), nest another discriminated union: Annotated[Union[BlockA, BlockB], Field(discriminator="name")] — the same pattern as BasisConfig, one level deeper.

apax/nn/builder.py — the abstract seam and three real subclasses (one method each!)
class ModelBuilder:
    def __init__(self, model_config: ModelConfig, n_species: int = 119):
        self.config = model_config          # a plain dict (model_dump())
        self.n_species = n_species

    def build_descriptor(self, apply_mask):
        raise NotImplementedError("use a subclass to facilitate this")


class GMNNBuilder(ModelBuilder):
    def build_descriptor(self, apply_mask):
        radial_fn = self.build_radial_function()          # reuse the base helper
        return GaussianMomentDescriptor(
            radial_fn=radial_fn, n_contr=self.config["n_contr"],
            dtype=self.config["descriptor_dtype"], apply_mask=apply_mask,
        )

class EquivMPBuilder(ModelBuilder):
    def build_descriptor(self, apply_mask):
        return EquivMPRepresentation(
            features=self.config["features"], max_degree=self.config["max_degree"],
            num_iterations=self.config["num_iterations"],
            basis_fn=self.build_basis_function(),
            dtype=self.config["descriptor_dtype"], apply_mask=apply_mask,
        )

class So3kratesBuilder(ModelBuilder):
    def build_descriptor(self, apply_mask):
        return So3kratesRepresentation(basis_fn=self.build_basis_function(),
            num_layers=self.config["num_layers"], max_degree=self.config["max_degree"],
            num_features=self.config["num_features"], num_heads=self.config["num_heads"],
            dtype=self.config["descriptor_dtype"], ...)

That is the whole story for a "normal" model: one method. The builder's build_energy_model() then composes your descriptor with the inherited readout, scale/shift, property heads and corrections.

06 The flax models & the contracts

You usually never touch apax/nn/models.py — but you must respect the two contracts it imposes on the pieces you supply: the descriptor contract and the readout contract.

Contract A Descriptor

def __call__(self, dr_vec, Z, idx) -> Array:
    # dr_vec : (n_neighbors, 3)  pair vectors
    # Z      : (n_atoms,)        atomic numbers
    # idx    : (2, n_neighbors)  (center, neighbor)
    ...
    return features   # MUST be (n_atoms, n_features)

Distances are precomputed for you. Return plain scalar features (not an IrrepsArray) at this boundary so the default readout can consume them. Honour apply_mask for padded atoms.

Contract B Readout

def __call__(self, x):     # vmapped over atoms
    # x : (n_features,) for ONE atom
    ...
    return h               # (1,)  or  (n_members,) for UQ

The model does jax.vmap(self.readout)(g), so your readout only ever sees a single atom's feature vector. Output width 1 = energy; width M > 1 = a shallow ensemble (see §07).

apax/nn/models.py — EnergyModel core (abridged): the two contracts in action
g   = self.representation(dr_vec, Z, idx)   # descriptor  → (n_atoms, n_features)
h   = jax.vmap(self.readout)(g)             # readout     → (n_atoms, 1) or (n_atoms, M)
E_i = self.scale_shift(h, Z)                # per-element scale & shift

is_shallow_ensemble = E_i.shape[1] > 1      # UQ is detected purely from the readout width
energy = fp64_sum(E_i, axis=0) if is_shallow_ensemble else fp64_sum(E_i)

for property_head in self.property_heads:   # charges, dipole, custom …
    properties.update(property_head(g, R, dr_vec, Z, idx, box))
for correction in self.corrections:         # ZBL, LatentEwald, …
    energy = energy + correction(R, dr_vec, Z, idx, box, properties)
return energy, properties

Axis 1 — Uncertainty is a config toggle (no code)

The default AtomisticReadout appends a final layer of width 1. When a shallow-ensemble config is present, that final width becomes n_members — and the downstream model code automatically detects the extra dimension and switches to the UQ path. You change uncertainty behaviour entirely from YAML.

apax/layers/readout.py — AtomisticReadout sizes its last layer from the ensemble config
def setup(self):
    units = list(self.units)
    if not self.is_feature_fn:
        readout_unit = [1]
        if self.n_shallow_ensemble > 0:
            readout_unit = [self.n_shallow_ensemble]   # ← widen → shallow ensemble
        units += readout_unit
    ...

apax/nn/models.py — ShallowEnsembleModel turns an ensemble of energies into mean + uncertainty
energy_ens, properties = self.energy_model(R, Z, neighbor, box, offsets)  # shape (n_members,)
energy_mean     = jnp.mean(energy_ens)
energy_variance = (1 / (n_ens - 1)) * fp64_sum((energy_ens - energy_mean) ** 2)
prediction = {
    "energy": energy_mean,
    "energy_ensemble": energy_ens,
    "energy_uncertainty": jnp.sqrt(energy_variance),   # ← uncertainty falls out
}

The variance follows the unbiased estimator \(\sigma_E^2 = \tfrac{1}{M-1}\sum_{k=1}^{M}\,(E_k-\bar{E})^2\), and forces get the same treatment via a per-member Jacobian.

Axis 2 — Swapping the readout module (override build_readout)

When your features don't fit a plain MLP head — say your descriptor emits a structured or per-layer feature layout — override build_readout in your builder to return a different module. As long as the new readout honours the per-atom vmap contract and the n_shallow_ensemble width convention, shallow-ensemble UQ keeps working unchanged.

🧱
Per-layer readout models (e.g. MACE). A model whose readout is applied per interaction layer still emits a single flat (n_atoms, n_features) descriptor — it just packs the per-layer scalars in layer order (n_features = num_interactions × hidden_dim). Its custom readout (e.g. MaceReadout) then derives the per-layer split from the input width (hidden_dim = x.shape[-1] // num_interactions) rather than taking a separately-configured width — so the readout can never desync from the descriptor's actual layout, and a layout mismatch fails loudly. Pass only genuine architectural constants (like num_interactions) to such a readout; never a width that merely duplicates what the descriptor already determines.

PropertyHead — extra outputs get UQ for free

Beyond energy, a PropertyHead reads the descriptor features g and emits any per-atom or aggregated property. It is symmetry-aware (mode: l0 scalar, l1 vector, symmetric_l2 / symmetric_traceless_l2 tensors) and, crucially, auto-detects an ensemble dimension and emits <name>_uncertainty alongside the mean — the same UQ machinery, reused.

apax/layers/properties.py — PropertyHead emits mean + uncertainty when fed ensemble features
output = {self.pname: result}
if is_ensemble:                              # detected from the readout width
    mean = jnp.mean(result, axis=0)
    uncertainty = (1/(n_ens-1)) * fp64_sum((mean - result) ** 2, axis=0)
    output[self.pname] = mean
    output[self.pname + "_uncertainty"] = uncertainty
return output
🧩
Takeaway. "Energy readout vs. UQ readout" is usually not a different class — it is the same readout asked to produce a wider output, plus a thin model wrapper, all selected by config. Reach for a custom readout module only when the feature layout itself is different.

10 Conventions & gotchas

Config side

  • extra="forbid" on every config — unknown keys are errors, not ignored.
  • Lazy import inside get_builder() — config ↔ nn would otherwise be circular.
  • Adding a model needs no __init__.pyi edit; it's reachable through the ModelConfig union (re-exported via apax.config).
  • Use precise pydantic types (PositiveInt, Literal[…]) — they become schema constraints and editor hints.

Builder / model side

  • Builder sees a dict (model_dump()): use self.config["x"].
  • Default n_species = 119 (full periodic table) drives per-element params.
  • Descriptor must return scalar features (n_atoms, n_features) — discard high-ℓ irreps at the boundary.
  • Respect dtypes: descriptor_dtype/readout_dtype default fp32, scale_shift_dtype fp64 (energy reductions stay fp64).
  • Honour apply_mask for padded atoms/neighbours (fixed-shape batching).
  • Keep the readout's n_shallow_ensemble width convention so UQ keeps working.
🔗
Cross-component dependencies are explicit. e.g. the latent_ewald correction needs a charges property head and raises a clear KeyError if it's missing. Prefer loud failures over silent zeros.
